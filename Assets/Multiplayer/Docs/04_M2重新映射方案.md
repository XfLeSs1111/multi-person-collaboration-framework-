# 04 — P2 M2 重新映射方案（单场景多房间）

> 状态：**设计定稿并已落地核心（2026-08-31）** · 依据：`03_任务落地书.md` P2 M2 段、Mirror `Examples/MultipleMatches`（`MatchNetworkManager` + `CanvasController` + `MatchController` + `NetworkMatch` + `MatchInterestManagement`）
> 一句话：原任务书的"五表 MatchManager + 全局删 EnsureRoom*"写在 P1 之前、面向旧 `SocketNetworkManager`（纯 NetworkManager）；P1 已改成 `SocketRoomManager : NetworkRoomManager` 全局切场景。**M2 单场景多房间与 NetworkRoomManager 的场景切换在根上冲突**，因此本方案把 M2 重新映射为：**基类降回 NetworkManager + 房间注册表 + NetworkMatch 兴趣隔离**，并把 P1 的房间功能（Leader/Ready/聊天/phase/ReturnToLobby）平移上来。

---

## 一、问题陈述：为什么不能照搬原设计

1. **场景切换是唯一阻塞项**。`NetworkRoomManager` 的整条流程（`ServerChangeScene(RoomScene⇄GameplayScene)`、`OnRoomServerCreateGamePlayer` 双 prefab 换人、`OnRoomServerSceneLoadedForPlayer` 身份拷贝）假定**全局只有一个房间**。两个房间无法同时各自切场景——同一时刻只有一个 active scene。
2. **`OnRoomServerPlayersReady`/`roomSlots` 是单房间语义**。roomSlots 是所有房间玩家的并集，没有房维度。
3. **原五表设计本身没错**（`playerMatches/openMatches/matchConnections/playerInfos/waitingConnections` 就是房间注册表），但它是给普通 NetworkManager 写的。P1 的 `SocketRoomPlayer`/`RoomOperations`/`NetworkPlayer`/`PcRoomHud`/`SocketRoomDiscovery` 全部要重新对准这个模型。
4. **兴趣隔离的硬约束**（`MatchInterestManagement` 源码）：`OnCheckObserver` 对 **`Guid.Empty` 返回 false**——空 matchId 的对象对所有人不可见。所以"没进房间的玩家"必须有一个真实的 matchId，否则连自己都看不见。→ 引出 D4 共享大厅房。

## 二、核心架构决策

| # | 决策 | 内容 |
|---|---|---|
| D1 | 基类 | `SocketRoomManager : NetworkManager`（**丢弃 NetworkRoomManager**）。房间注册表内置，override `OnServerAddPlayer/OnServerReady/OnServerConnect/OnServerDisconnect`（P2.9 已授权打破 P1 红线）。 |
| D2 | 玩家实体 | 单一 `playerPrefab` = `NetworkPlayer` + `NetworkMatch` + `LocalPlayerInput` + `NetworkTransformUnreliable` + `CharacterController`。**删掉双 prefab 换人**（`SocketRoomPlayer`、`roomPlayerPrefab`、`OnRoomServerCreateGamePlayer` 全部废弃）。身份（名字/颜色/Leader）直接 `[SyncVar]` 在 NetworkPlayer 上，入房时由服务器赋。 |
| D3 | 兴趣隔离 | 场景放一个 `MatchInterestManagement`（DDOL manager 对象）。所有 spawn 的对象（玩家、交互物、每房 RoomState/Chat、每房 RoomEnvironment）带 `NetworkMatch.matchId = 房 Guid`，隔离自动生效。 |
| D4 | 共享大厅房 | 常量 `LobbyRoom.Id`（非空 Guid）。客户端一连接，其玩家对象 matchId = 大厅房 → 大厅成员互相可见 + 大厅聊天。Create/Join 真实房时把玩家 `NetworkMatch.matchId` 改到房 Guid（setter 自动触发 observer 重建）。 |
| D5 | 场景 | 单场景常驻（Lobby 场景资产：地板 + StartPositions）。"开始游戏"不再是切场景，而是：房 phase=Lobby→InGame + **Room 级 spawn** 交互物（matchId=房 Guid）；RoomEnvironment 视觉容器留作下一阶段。返回大厅 = 反操作。 |
| D6 | 消息 | 协议走 `ServerRoomMessage` / `ClientRoomMessage`（P2.7 `RoomMessages.cs`，照抄 `MatchMessages` 六操作 + 房间名/phase/Leader）。客户端入房是消息驱动，不是切场景。 |
| D7 | 发现 | `Response` 加 `rooms[]`（P2.13）：每服务器广播**该服务器上的所有房间**（每房 name/players/max/phase），客户端合并进本地表。M1 的 `Servers` 快照升级为 `ServerEntry { RoomInfo[] rooms; lastSeen }`。 |

## 三、实体模型（对象图）

```text
Server 常驻场景（原 Lobby 场景：Floor + StartPositions，永不切换）
│
├─ SocketRoomManager（NetworkManager，DDOL）   ← 房间注册表 + MatchInterestManagement 组件 + discovery
│
├─ 大厅房（LobbyRoom.Id，隐形逻辑房）
│   ├─ 每个已连接未入房玩家 NetworkPlayer（matchId=LobbyRoom.Id）
│   └─ 大厅 NetworkRoomChat / NetworkRoomState（matchId=LobbyRoom.Id）
│
├─ 房 A（Guid_A）
│   ├─ 玩家甲/乙 NetworkPlayer（matchId=Guid_A）
│   ├─ NetworkRoomChat A（matchId=Guid_A）  ← 聊天只在本房广播（兴趣隔离）
│   ├─ NetworkRoomState A（matchId=Guid_A） ← phase/人数
│   └─ phase=InGame 时：RoomEnvironment A + Interactable×3（matchId=Guid_A）
│
└─ 房 B（Guid_B）…… 与 A 完全隔离，房主 Start 只影响 B
```

## 五、实施顺序（每步保持可编译）

1. **P2.7** `RoomMessages.cs`（纯新增，零侵入）✅ 本方案随附
2. **M2-core** 重写 `SocketRoomManager : NetworkManager`（注册表 + 消息 handler + 入口 override）——已落地；`SocketRoomPlayer.cs` 暂留为旧资产兼容壳，但新生成路径不再使用

## 六、验收标准映射

| 原验收 | 落地后怎么验 |
|---|---|
| 单端口两客户端建两房，A 看不到 B 玩家/交互物 | 同一 Server，客户端甲 Create 房A、乙 Create 房B；甲 Start → A phase=InGame+环境 spawn，乙视角看不到 A 的任何对象（NetworkMatch 隔离） |
| 房间列表显示两房及人数/phase；入房隔离；聊天只在本房 | 大厅列表显示 A/B（人数/phase）；Join 后只收到本房聊天与 RoomState |
| 房 A Start → A phase=InGame+环境 spawn，房 B 保持大厅 | 房间注册表 phase 独立；RoomEnvironment spawn 只带 A 的 matchId |
| 连接后收到 `ClientRoomMessage.List` 同步最新列表 | `SendRoomList` 推给大厅房成员 + 新连接立即下发 |

## 七、偏差登记（相对原任务书 M2）

① 原 P2.8"新 SocketRoomManager"实际是**重写现有** `SocketRoomManager`；② 原 P2.9"SocketNetworkManager 改造"失效（P1 已删，并入 M2-core 的入口 override）；③ 原 P2.10 新增"按本机玩家 matchId 取房"（**不再 FindFirstObjectByType**）沿用；④ 原 P2.12 环境 spawn 沿用，但**交互物从 Game 场景改由每房 spawn**（单场景下 Game 场景资产不再存在）；⑤ D4 共享大厅房是原设计没有的概念（MatchInterestManagement 对 Guid.Empty 不可见逼出来的）；⑥ M2 落地后 P1 的全局 `RoomState/Chat` DDOL 改为每房 spawn。
