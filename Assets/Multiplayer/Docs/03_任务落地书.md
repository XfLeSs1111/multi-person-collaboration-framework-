## 〇、执行总则

1. **顺序不可打乱**：P0 → P1 → P2 严格串行（P2 依赖 P1 的 `NetworkRoomManager` 基类；P1 依赖 P0 的资产重建）。P3/P4 可在 P1 之后与 P2 并行（P4 依赖 P1 完成后的类结构）。
2. **分支策略**：每个阶段独立分支，合回 `master` 后打 tag。
   ```text
   master ─ P0 ── P1 ── P2 ── P3/P4
             │feat/p0-fixes  │feat/p1-room-manager  │feat/p2-multiroom
   ```
3. **可验收才提交**：每阶段末跑该阶段验收清单（见各阶段末），并更新 `02_落地实施计划.md` 的勘误。
4. **遇到调研结论与实现不符时**：以实际编译/运行为准，把偏差记录到各阶段"偏差登记"栏，不要静默改设计。
