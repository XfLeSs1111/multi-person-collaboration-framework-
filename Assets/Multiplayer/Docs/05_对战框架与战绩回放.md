# 05 — 对战框架与战绩/回放

> 状态：**已落地（2026-09-11）** · 依据：`04_M2重新映射方案.md` 的房间模型 + 本轮需求（对战判定、特殊情况、配置优先、战绩、回放）
> 一句话：把"每局对战都绕不开的东西"沉到框架层，游戏只做规则与表现；策略性取值一律进配置中心。新增玩法 = 一个派生适配器 + 一个预制体 + 一份规则资产。

---

## 一、分层与职责

| 层 | 位置 | 职责 |
|----|------|------|
| 配置层 | `MultiplayerConfig` / `RoomTemplate`（Odin 配置中心） | 时限、战绩条数、回放开关、人数/座位/观战上限等**策略**；参与协议签名 |
| 内核层 | `MatchSession` / `MatchPrimitives` / 游戏规则 | 纯逻辑：回合、规则判定、事件流、**结构化拒绝原因**、结束原因与判负起因 |
| 适配层 | `NetworkMatchAdapter`（抽象）+ `NetworkGomokuMatch` | 回合计时、认输命令、座位名单、战绩生成；游戏实现 9 个服务端钩子 + 3 个文案钩子 |
| 房间层 | `SocketRoomManager` / `RoomRegistry` | 房间生命周期与匹配路由，**只认框架基类**，不知道具体玩法 |
| 表现层 | `MultiplayerUi.*` | 只读框架接口渲染；棋盘等玩法皮肤留在游戏侧 partial 文件 |

## 二、对战必须有的情况（框架统一提供）

| 情况 | 机制 |
|------|------|
| 非自己回合 | 客户端棋盘不可点（`IsLocalTurn`），服务端仍兜底并回传结构化原因 |
| 非法落子 | `MatchRejectReason` → `MultiplayerErrorCode` → 状态栏中文提示（不解析字符串） |
| 认输 | 基类统一 `CmdResign()`（限流 + 校验），结束原因为 Forfeit/Surrender |
| 掉线 / 离开 | 对局中判负、**房间保留**；等待阶段退席；胜者留在房里可继续 |
| 超时 | `config.turnTimeoutSeconds`；服务器 1s 扫描，当前该落子方判负 |
| 和棋 | 满盘 + 允许和棋（内核 `AllowDraw`） |
| 再来一局 | 房间 `InGame → Lobby` 自动复位：清准备 + 房主按钮变"再来一局"；开局时重置棋盘并重绑座位 |
| 对战 / 观战 | 座位名单 `SyncList<MatchSeatInfo>`；超过 `MaxSeats` 的房间成员自动进观战席（seat=-1），UI 显示"黑棋 X / 观战" |
| 同步自愈 | 服务器 1s 按注册表校正成员房间/座位，避免建房与玩家生成竞态导致"有房间但无座位"（棋盘点不动） |

## 三、战绩与回放

```text
MatchSession 事件流(IMatchEventSink)
  -> 游戏适配器 ServerCreateRecord()：结果/结束原因/座位摘要 + 游戏自定义回放 payload
  -> MatchRecordBook（每房有界，条数=config.matchRecordLimit；0=关闭）
  -> ClientRoomMessage.matchRecords 下发（协议布局变更 → Version 递增）
  -> UI 战绩列表（倒序）→「回放」按钮
  -> 客户端本地重放：纯逻辑内核重建状态并逐步渲染（不经过服务器）
```

- **框架只搬运 payload，不解析**：格式由游戏定义（五子棋 `index:颜色` 序列）。
- 回放不需要网络：规则内核无 Unity 依赖、随客户端编译；`MultiplayerUi.Replay.cs` 逐手 `TryApply` 重建。
- 关闭回放只留结果，内存不随对局增长。

## 四、新增玩法的落地清单

1. 派生 `NetworkMatchAdapter`：`ServerInitialize / StartMatch / ResetMatch / Forfeit / AddPlayer / AddSpectator / DropParticipant / SetParticipantConnected / FindStableIdBySeat` + `DescribeSeat / DescribeResult / ServerCreateRecord`。
2. 规则写进纯逻辑内核（无 UnityEngine），并加入 `ci/PureLogic.Tests` 才会被 CI 覆盖。
3. 预制体挂 `NetworkIdentity + NetworkMatch + 适配器`，生成器把 `matchPrefab` 指过去。
4. 策略参数先加配置项（含校验与协议签名），再谈代码默认值。

## 五、已知遗留

- 观战者**补位**：座位空出后不自动上桌，等下一局 `ResetMatch + RebindMatchParticipants` 时按顺序重排。
- 回放仅逐手（◀/▶/退出），无自动播放与进度条。
- 3 人房观战标签、战绩与回放需双端实测确认（MCP 自动化在建房消息路径上偶发静默失败，未复现根因）。
